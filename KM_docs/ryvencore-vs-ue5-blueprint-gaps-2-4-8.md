# 相对 UE5 蓝图的改进方向（摘录：类型系统、编辑效率、信息密度）

本文档记录与 UE5 蓝图系统对比时，**当前流图栈**（Ryven / ryvencore + ryvencore_qt 及上层业务）在以下三方面的**差距与可改进点**，便于排期与架构讨论。

定位说明：UE5 蓝图为引擎内一等公民的可视化脚本；本栈为通用 **Qt 节点编辑器 + Python 执行模型**。对比目的为取长补短，而非要求功能对等。

---

## 2. 类型系统与连线安全

**UE5 侧特征**

- Pin **强类型**，自动转换规则明确（含 Make/Break、Enum、软引用等）。
- 大量错误在**编辑期**即可拦截，连线语义清晰。

**当前系统常见缺口**

- 通用节点图多为**弱类型或半类型**；若端口层未做严格校验，易出现**运行时才暴露**的数据流错误。
- 类型不统一时，难以做「仅显示可连接目标」等智能提示。

**改进方向（建议）**

- 在端口/连接层建立 **类型代数或标签体系**（含兼容矩阵、向上/向下转型规则）。
- **编辑期校验**：连线时拒绝非法连接，并在 UI 上给出原因（而非静默失败）。
- 对高频数据类型：**结构化预览**（悬停或 Inspector 中展示字段摘要），降低「黑盒连线」风险。

## 4. 节点发现与编辑效率

**UE5 侧特征**

- 右键菜单、**从 Pin 拖出上下文相关节点**、海量内置节点库。
- **宏 / 折叠图 / 函数图**、跳转定义、跨蓝图引用等提升大图维护效率。

**当前系统常见缺口**

- 已有 FlowView、节点列表、Inspector 等基础能力，但在**上下文敏感推荐**、**全局搜索引用**、**跨图跳转**、**批量重命名**等方面通常仍弱于 UE。
- 大图下「找节点、改一处牵全身」的成本偏高。

**改进方向（建议）**

- **从端口拉线**：根据类型与语义弹出可连接节点候选（可结合简单评分排序）。
- **全局/流内搜索**：按标题、类型、标签、注释检索节点与引用关系。
- **子图/折叠**：与 ryvencore 的 Flow 模型对齐的复用单元（宏、函数图或等价抽象），并支持「跳转到定义 / 返回」。
- **批量重构**：重命名同步、废弃节点迁移提示。

## 8. 主题表现与信息密度

**UE5 侧特征**

- 偏**工程向信息密度**：Pin 颜色语义、类型区分、暗色主题与图标体系统一。
- 装饰服务于**可读性与错误扫描**，而非单纯视觉。

**当前系统相关现状**

- `FlowTheme` / `Design` 已支持多套皮肤与圆角、渐变等表现（见 `KM_docs/vendor-ryvencore-qt-node-appearance.md`）。
- 若主题以「好看」为主、**类型语义色**未与主题解耦，可能出现装饰盖过信息的问题。

**改进方向（建议）**

- **高密度布局模式**（可选）：紧凑 Pin 间距、可选隐藏冗余装饰，利于大图。
- **Pin / 连线颜色规范**：与 `FlowTheme` 解耦一层「语义色板」（exec/data/类型族），主题切换时保持可辨识性。
- **可访问性**：对比度、色弱友好模式；关键状态（选中、错误、断连）不唯一依赖色相。
- 在「漂亮模式」与「扫图模式」之间提供**显式切换**（可与现有 `pretty` / `fast` 性能档位协同或独立配置）。
